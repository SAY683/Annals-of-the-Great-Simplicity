### 0.2 执行原则 (Round 21 宪章)

1. **应优尽优**: 任何已识别的优化机会，若 30 分钟内可落地，立即执行
2. **应整尽整**: 跨项目不一致的代码/配置/文档，统一整合
3. **应追尽踪**: 任何调用链必须能从入口追到出口，断点必查
4. **应修尽缮**: 已发现的 bug/债务，本轮内修复并验证
5. **应注尽释**: 任何非自明的代码/数学/决策，必须有注释或文档
6. **盲区觉知**: 若本轮查不到但下轮发现，记录为"认知盲区"并归档

### 2.1 [P0-A] 5 项目 HTTP API 全量审查 (需求 #1, #5)

**目标**: 确保所有路由可调度、错误处理完备、生产级可用。

**步骤**:
1. 用 memory-mcp `search_graph` 提取每项目的 Route 节点
2. 对照实际 server.js/api.py 代码，标注每个路由的:
   - HTTP 方法 + 路径
   - 入参校验 (UUID/类型/范围)
   - 错误响应 (4xx/5xx 是否有 friendly message)
   - 鉴权 (是否需要 API Key)
   - 限流 (是否有 rate limit)

3. 输出 `ROUND21_API_AUDIT.md` 路由审查矩阵

**验收标准**:
- 5 项目所有路由 100% 覆盖
- 每路由 6 项指标齐全
- 至少 1 个端到端联调 (trace-engine-web → trace-to-edm → edm-takens-web)

### 2.2 [P0-B] 算法数学审查 (需求 #2, #4)

**目标**: 防止"显著错误却汇报无误"的重演。

**审查范围** (按算法核心度排序):

| 模块 | 文件 | 关键数学 | 审查重点 |
|------|------|---------|---------|
| CCM 因果方向 | ccm_causality.py | Spearman ρ 收敛 + Benjamini-Hochberg FDR | ρ 收敛判定 4 条件 + p 值校正 |
| HAVOK 稳定性 | sovereign_havok.py | Hankel + SVD + 强迫项 + Lyapunov | q_eff<3 边界 + λ 分类阈值 |
| EDM 自适应 | edm_adaptive_pipeline.py | EmbedDimension + Simplex + S-Map | S-Map 数值稳定性 |
| Lyapunov 指数 | final_interpretation.py | Rosenstein 算法 + R² 门控 | N<100 不可靠标记 |
| DoWhy 桥接 | counterfactual_bridge.py | EstimandType + backdoor + adjustment_set | 不可识别披露 |
| Pearl 反事实 | pearl_counterfactual.py | 三步反事实 (abduction/action/prediction) | ITE 计算 |
| PCA Procrustes | layer2_semantic.py (trace-to-edm) | Orthogonal Procrustes + 符号修正 | 跨项目主轴对齐 |
| ZScoreNormalizer | layer3_sacred.py | 标准化 + 异常处理 | 数值边界 |

**步骤**:
1. 对每个模块用 `get_code_snippet` 提取关键函数
2. 数学家视角: 核对公式与实现的一致性
3. 统计家视角: 核对假设检验、p 值、置信区间的正确性
4. 输出 `ROUND21_ALGORITHM_AUDIT.md`

**验收标准**:
- 8 个模块全部审查
- 每模块至少 1 个数值示例验证
- 发现的问题按 P0/P1/P2 分级

## 4. 元反思机制 (需求 #6, #7)

### 4.1 认知盲区归档

每轮结束, 回答 3 个问题:
1. **本轮发现了什么之前未发现的问题?**
2. **本轮有什么问题查了但没查到, 需要下轮继续?**
3. **本轮的检察方法是否有遗漏, 导致盲区?**

### 4.2 4 角色互审

每轮关键决策, 用 4 角色交叉验证:
- **PM**: 用户能否理解? 操作是否流畅?
- **算法工程师**: 实现是否正确? 性能是否可接受?
- **数学家**: 公式是否一致? 边界条件是否处理?
- **统计家**: 假设是否满足? p 值/CI 是否正确解读?
