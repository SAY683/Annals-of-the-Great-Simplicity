# TRACE 指标解释词典（TRACE Interpretation Dictionary）

> **设计目标：** 让不熟悉因果推断 / EDM / Takens 嵌入等算法的用户，也能读懂 TRACE 引擎输出的每一个指标。
>
> **阅读指南：** 每条指标包含四个维度 —— **术语**（你在哪里看到它）、**通俗解释**（一句话说明）、**比喻**（用日常事物类比）、**刨析**（严谨的算法原理和判断准则）。

## 1. 桥接参数（Bridge Parameters）

这些参数在任务启动时以日志形式输出，是引擎的"控制旋钮"。

### threshold（因果边阈值）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 多"强"的因果关系才值得被画进因果图。 |
| **比喻** | 就像地震台网设定"震级阈值"——3 级以下的地震每天发生几千次但你感觉不到，只有 ≥5 级的才会上新闻。threshold 就是因果信号的"震级下限"。 |
| **刨析** | 取值范围 0.001–5.0。TRACE 引擎用 ΔNLL（负对数似然变化量）衡量 token A 对 token B 的因果强度。低于 threshold 的边被认为噪声或偶然共现，直接丢弃。 **越低**，因果图越密集（可能含假阳性）；**越高**，因果图越稀疏（可能漏掉重要关系）。Web 默认值 0.03 适合通用文本。 |

### concept_min_freq（概念最低出现次数）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 一个词至少出现几次才被视为"有意义的主题概念"（而非偶然提及）。 |
| **比喻** | 就像新闻编辑筛选话题——"出现一次的是闲谈，反复出现的是议题"。一个词只提了一次可能是随口一说；反复提三次说明它确实是文章讨论的核心。 |
| **刨析** | 取值范围 1–10。TRACE 对 token 序列做频率统计，出现次数 ≥ concept_min_freq 且通过有效性检查的 token 才能成为独立概念节点，否则归入 `<other>` 聚合节点。默认值 2 允许低频但关键的概念浮现。 |

### max_edges_for_dowhy（最大边数）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 因果图中最多允许多少根箭头（因果边）。上限定在不至于让后续分析算不动。 |
| **比喻** | 就像论文的参考文献页数限制——PhD 论文可以引用 200 篇文献，但两页的会议短文最多只能引用 8 篇。因果图也一样，边数过大会导致 DoWhy 引擎崩溃。 |
| **刨析** | 取值范围 3–50。超过此限制的边按 filter_mode 策略截断（取最强的 top-N 或 percentile 过滤）。Web 默认 8 是平衡计算速度与覆盖率的经验值。 |

### filter_mode（边过滤模式）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 当候选因果边太多时，用"什么规则"砍掉较弱的边。 |
| **比喻** | 三个模式对应三种选秀规则：**topn** = "只留前 8 名"（冠军制）；**percentile** = "只留排名前 85% 的"（优等生制）；**adaptive** = "先看竞争激烈程度再决定用哪种规则"（灵活制）。 |
| **刨析** | `topn`：按 ΔNLL 从高到低取前 N 条；`percentile`：取 ΔNLL 高于指定百分位的边；`adaptive`：先计算图密度，密度高时用 percentile（全局过滤），低时用 topn（保留最强信号）。 |

### filter_percentile（过滤百分位）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 在 percentile 模式下，只保留因果强度排在前 X% 的边。 |
| **比喻** | 相当于"录取分数线"——85 意味着你只招排名前 85% 的学生，最后 15% 淘汰。 |
| **刨析** | 取值范围 50–99。仅在 filter_mode=percentile 或 adaptive 时生效。结合 threshold 形成一个"双重门槛"：先过 threshold（绝对门槛），再过 percentile（相对门槛）。 |

### random_state（随机种子）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 固定随机数生成的起点，保证每次运行结果一致（可复现）。 |
| **比喻** | 就像 Minecraft 地图种子——输入相同的种子，每个人生成的世界完全一样。设为 42 只是一个程序员梗（《银河系漫游指南》中"生命、宇宙与一切的终极答案"）。 |
| **刨析** | 影响 bootstrap 抽样、SEM 数据模拟等涉及随机数的步骤。同一输入文本 + 相同随机种子 = 完全相同的输出，这是科学可复现性的基本保障。 |

### classical_mode（古汉语模式）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 是否用古文阅读模式——保留"之乎者也"等文言虚词作为有效概念。 |
| **比喻** | 就像切换词典：现代汉语词典会把"之"标记为"助词，无实义"直接跳过；但如果你在读《庄子》，"之"可能是关键哲学概念，需要保留。 |
| **刨析** | 默认为 false。开启时，`is_valid_concept()` 过滤规则会保留古汉语虚词（之/乎/者/也/矣/焉/兮等），因为它们在先秦/宋明理学文本中承载实质语义。 |

### window_size（窗口大小）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 分析一段文本时，一次"视野"扫描多少个 token。 |
| **比喻** | 就像读书时一眼看多少字——窗口太小（如 2）只能看到"的""了"等局部词；窗口适中（64）能看到一整句话内的因果互动；窗口太大（256）可能把不相关的段落也扯上关系。 |
| **刨析** | SUPER 模式下控制 TRACE 滑动窗口的 token 数。Web 普通模式用共现窗口构建概念级图，默认 64 适合中文（约等于 3-5 个句子的语义跨度）。 |

### max_segments（最大分段数）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 长文本最多切成几段分别分析（防止 GPU 显存溢出）。 |
| **比喻** | 一部 500 页的小说不可能一次分析完——分成 4 卷，每卷独立扫描，最后汇总。 |
| **刨析** | SUPER 模式参数。但分段会割裂跨段落的因果链，段数越少越能保留全局因果结构。 |

## 2. 数据诊断指标（Data Diagnostics）

这些指标描述"输入数据长什么样"，帮助判断分析质量的上限。

### raw_tokens / valid_concept_tokens（原始 token 数 / 有效概念 token 数）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 全文切词后所有词的总数 vs 去掉标点、虚词、无意义碎片后剩余多少。 |
| **比喻** | raw_tokens 是你菜篮子里所有东西（菜叶 + 泥土 + 塑料袋）；valid_concept_tokens 是洗净择好的净菜。渣土率 = 1 − (净菜/总重)，这个比例如实反映了文本"因果分析价值"的密度。 |
| **刨析** | 有效性由 `is_valid_concept()` 判断：剔除标点、单字 BPE 碎片、停用词、纯数字等。比值过低（<0.3）提示文本可能不适合因果分析。 |

### concept_coverage（概念覆盖率）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 全文中有多少比例的 token 能被归类到某个"概念节点"中。 |
| **比喻** | 就像一张地图的覆盖率——如果一张城市地图只有 30% 的街道被标出了，那它很难用来导航。同理，概念覆盖率低意味着大量文本信息被丢弃了。 |
| **刨析** | `len(valid_tokens) / len(raw_tokens)`。高覆盖率（>0.6）说明文本概念密集、适合分析；低覆盖率提示文本含大量噪音（如代码、表格、乱码）。 |

### adj_density（邻接矩阵密度）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 概念之间的因果边占所有可能边的比例。 |
| **比喻** | 就像社交网络中"好友关系"的稀疏度——如果 100 人中只有 3 对是好友，这个圈子是松散的；如果有 500 对好友关系，这个圈子非常紧密。因果图密度同理：低密度 = 概念之间独立性强；高密度 = 概念纠缠复杂。 |
| **刨析** | `(adj > 0).sum() / adj.size`。理想范围 0.05–0.3。密度 >0.5 提示阈值设得太低或文本中几乎所有概念都相关，可能导致 DoWhy 算不动。 |

### max_delta_nll（最大因果信号强度）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 因果图中"最强的那根箭头"有多强。 |
| **比喻** | 一场对话中，哪个词最"霸凌"其他词——它一出现，其他词的出现概率就剧烈改变。max_delta_nll 就是那个"霸主"的影响力度。 |
| **刨析** | ΔNLL（负对数似然差）衡量一个 token 出现后另一个 token 出现概率变化的剧烈程度。max_dnl > 2.0 说明存在很强的因果信号；max_dnl < 0.5 可能说明文本因果结构弱。 |

### bpe_type（BPE 类型）/ unk_rate（未知词率）

| 维度 | 内容 |
|------|------|
| **通俗解释** | BPE 类型告诉你是"按字切"还是"按词切"的分词方式；UNK 率告诉你分词的"生词失效率"有多高。 |
| **比喻** | BPE 类型就像你用的菜刀类别——中式片刀切方块菜（词级）、西式主厨刀可切片也可切丝（子词级）。UNK 率就像"用这把刀切不动的硬食材比例"——高 UNK 率说明工具和食材不匹配。 |
| **刨析** | `unk_rate > 0.2` = 严重跨域，强烈建议用 Instant TRACE 训练专属模型；`unk_rate > 0.05` = 中度跨域，建议降低 threshold；`unk_rate < 0.01` = 正常。 |

### condition_number（条件数）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 数据矩阵的"病态程度"——条件数越高，数值计算越不稳定，结果越不可信。 |
| **比喻** | 就像天平的量程——天平称 100g 的东西很准，但如果你用同一个天平去称一粒米（信号接近噪声水平），读数会剧烈抖动。条件数就是把"最小可称物"和"最大量程"对比。 |
| **刨析** | `max_eigenvalue / min_eigenvalue`。条件数 < 100 正常；100–1000 需要注意（可能存在共线性）；>1000 时回归系数的估计极不稳定（严重多重共线性），SEM 系数可能不可信。 |

### max_correlation（最大相关系数）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 任意两个概念之间"线性相关"的最高程度。 |
| **比喻** | 就像两个跳舞的人同步率——0.95 相关性意味着"A 做什么 B 就做什么"，几乎完全同步；-0.95 意味着"A 做啥 B 做反啥"。极端相关可能导致因果分析把"同步"误判为"因果"。 |
| **刨析** | 绝对值 > 0.98 提示可能存在重复列或完全线性依赖，OLS 估计会不稳定。 |

### min_eigenvalue（最小特征值）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 概念数据的"维度失效率"——特征值越大说明数据在那个方向上有丰富的变异，越接近零说明在那个方向上几乎是平坦的（没有信息量）。 |
| **比喻** | 就像看一幅画——如果画的某些区域完全是纯白色（无纹理、无变化），那摄影师从这个角度拍不到任何东西。最小特征值就是"最白的那个区域"的色差程度。 |
| **刨析** | 接近 0 表示存在严重的共线性，一个或多个概念可以用其他概念的线性组合表示（没有独立信息）。 |

## 3. 概念与图结构指标（Concepts & Graph）

### 概念列表（concepts）与 CCM 资格（ccm_eligible_concepts）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 文本提取出的"核心概念词"，以及其中哪些有足够数据做 CCM（收敛交叉映射）非线性因果验证。 |
| **比喻** | 提取概念 = 从一篇文章中选出"关键词"——你读完一篇文章后能概括出的 12 个主题词。CCM 资格 = 这些关键词中哪些被讨论了足够多次，可以用"测谎方法"验证因果关系是否真实。 |
| **刨析** | 概念由高频 token 按频率排序取 top-N（max_concepts）得到。CCM 资格要求概念出现 ≥3 次（CCM 算法需要足够多的出现点来做时间序列交叉映射）。CCM 资格率低 → 文本倾向叙事文（概念稀疏）。 |

### 显著因果边（significant_edges）/ Top 边

| 维度 | 内容 |
|------|------|
| **通俗解释** | 通过 threshold 筛选后保留的因果箭头——"C2→A3"意味着"C2 的发生导致 A3 的发生概率显著改变"。 |
| **比喻** | 显著边就是你做完所有统计检验后还剩的那些"有把握的结论"。图表中的 Top-5 边 = 论文中放在主页的那几个核心发现。 |
| **刨析** | 每条边是一个三元组 `(source, target, ΔNLL_strength)`。方向"→"表示有向因果关系（source → target 的 ΔNLL 显著高于反向）。强度数值含义：ΔNLL=8.0 是极强信号，ΔNLL=0.1 是弱信号。 |

### 邻接矩阵（adjacency_matrix）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 一张 N×N 的数字表格，第 i 行第 j 列的数字 = 概念 i 对概念 j 的因果影响强度。 |
| **比喻** | 就像社交网络的"影响力矩阵"——每行是一个 influencer，每列是一个 follower，数字代表影响力大小。零表示"互不关注"。 |
| **刨析** | 矩阵对称化处理：通过有向边计数比较（如果 i→j 的次数 > j→i 的次数，则方向为 i→j，反向清零）。非零元素总数 = 候选边数。 |

## 4. 因果效应指标（Causal Effect）

### ATE（Average Treatment Effect，平均处理效应）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 如果把"原因"从 0 调成 1，**平均而言**"结果"会变多少。 |
| **比喻** | 医生想知道"吃这药平均能让血压降多少"——ATE 就是吃药的 1000 人中，血压的平均降幅。ATE=-0.38 意味着"原因每增加 1 单位，结果平均下降 0.38 单位"。 |
| **刨析** | 计算公式：E[Y|do(T=1)] − E[Y|do(T=0)]。`do(T=1)` 表示"人为干预"（非自然观察），这是因果推断与相关分析的根本区别。ATE 绝对值越大说明效应越强，但必须结合 CI 来看——如果 CI 跨零，即使 ATE 很大也"不显著"。正负号的含义：正 = 原因增加 → 结果增加；负 = 原因增加 → 结果减少。 |

### 95% CI（Confidence Interval，置信区间）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 真实因果效应有 95% 的概率落在这个区间内。 |
| **比喻** | 就像射箭——你射出 100 支箭，95 支箭落在一个圆环内，CI 就是这个圆环的半径范围。如果 CI 不包含 0（比如 [-0.53, -0.24]），你可以说"效应是统计学显著的"。如果 CI 包含 0（比如 [-0.10, +0.08]），则"无法确定因果效应存在"。 |
| **刨析** | LIGHT 模式用 OLS 解析解直接计算（快速），非 LIGHT 模式用 DoWhy bootstrap 估计。CI 宽度取决于样本量和数据方差——样本越小/方差越大，CI 越宽。 |

### confidence_method（置信度计算方法）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 用"什么方法"算出来的置信区间——决定了区间精度的"制造工艺"。 |
| **比喻** | OLS-analytic = 用精确数学公式算出来的，就像工厂流水线标准化生产；bootstrap = 用反复随机抽样算出来的，就像手工测量 1000 次取平均值；SEM-analytic = 用因果结构方程模型推出来的。 |
| **刨析** | LIGHT 模式固定使用 `OLS-analytic`（最快，适合快速分析）；DEEP 模式可能用 `bootstrap`（更稳健但慢）；模拟模式用 `SEM-analytic`。 |

### identifiable（可识别性）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 从现有观测数据中，能否唯一地算出因果效应（而非相关关系）。 |
| **比喻** | 就像刑侦破案——"指纹和DNA都吻合"= 可识别（多重证据交叉验证）；"只有目击者口供，没有物证"= 不可识别（无法排除混杂因素的干扰）。 |
| **刨析** | DoWhy 用 do-calculus 判断：给定因果图和观测数据，`P(Y|do(T))` 是否可以被表达为仅涉及观测分布的表达式。True = 因果图中没有未观测共因（后门路径被阻断）；False = 至少存在一条未被阻断的后门路径。 |

### estimand_type（估计类型）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 因果效应是用"什么数学手法"算出来的——每种手法对应不同的数据假设。 |
| **比喻** | 就像不同的测量工具——backdoor 是"用控制变量法消除混杂"（你控制住所有可能的干扰因素）；iv 是"找一个天然随机化的工具变量代替原因"（用抽签决定谁吃药）。 |
| **刨析** | 最常见的是 `backdoor`（后门调整）：通过调整共因变量来消除混杂偏倚。还可能是 `frontdoor`（前门调整）或 `iv`（工具变量）。 |

## 5. 反驳测试指标（Refutation）

### 随机共因反驳（random_common_cause）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 如果"凭空添加一个随机噪声干扰因素"，我们之前发现的因果效应会不会被推翻？ |
| **比喻** | 就像地震学家问自己："如果我们发现的地震前兆只是随机噪声，那预测地震的准确度会降多少？"——如果加随机噪声后效应仍然稳健，说明真正的因果信号足够强大。 |
| **刨析** | 向数据中添加一个随机生成的共因变量，然后重新估计效应。如果原始 ATE 和新 ATE 偏差 < 30%，判定为 ✓ 稳健（效应不是数据中偶然相关的结果）。 |

### 安慰剂处理反驳（placebo_treatment_refuter）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 如果把"原因变量"换成另一个无关的随机变量（但保持它和原变量的统计特性），效应是否消失？ |
| **比喻** | 就像医药实验中的安慰剂对比——给对照组吃糖豆（看起来像真药，但没有药物成分）。如果糖豆也产生了类似真药的效果，说明"疗效"可能只是心理作用。如果糖豆没有效果，说明真药确实有效。 |
| **刨析** | 创建一个与原始 treatment 统计特性相同但独立于 outcome 的"假 treatment"变量。如果假 treatment 的效应接近 0，则 ✓（因果归因正确）；如果假 treatment 仍然有效，则 ⚠️ 反驳（原效应可能来自统计伪影）。 |

### 数据子集反驳（data_subset_refuter）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 如果把数据切掉一部分（如随机丢弃 20% 的样本），因果效应是否仍然成立？ |
| **比喻** | 就像考试验证——如果你声称"这套教材能提分"，那把学生随机分成两组，每组用教材的不同子集，两组提分效果应该差不多。如果一组提分、一组不提，说明效应不稳定。 |
| **刨析** | 随机选取原始数据的一个子集（默认 80%），在子集上重新估计效应。如果 ATE 在新子集上偏差过大，则 ⚠️ 反驳（效应依赖特定样本，非普遍规律）。 |

### refuted / deviation / display_metric（反驳判定 / 偏差 / 显示指标）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 三个指标构成一条反驳测试的结果摘要：**判定**（通过/未通过）、**偏差**（新效应偏离原效应的程度）、**显示指标**（用什么方式量化偏差）。 |
| **比喻** | 就像驾考评判——refuted = 挂科/通过；deviation = 你离满分差多少分；display_metric = 用的是扣分制还是及格制。 |
| **刨析** | refuted 的判定标准：随机共因用偏差度阈值 30%；安慰剂用 new_effect 是否接近 0；数据子集用 ATE 偏差度。0 次被反驳 = 效应非常稳健；2-3 次被反驳 = 效应可能不稳定，需要进一步检查。 |

## 6. 反事实扫描指标（Counterfactual Scan）

### ITE（Individual Treatment Effect，个体因果效应）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 在"这一个特定的观测样本"上，改变原因会导致结果变化多少（与 ATE 的平均效应相对）。 |
| **比喻** | ATE 是全班的"平均提分"——"上补习班能让全班平均提 5 分"。ITE 是"小明这个人上了补习班能提几分"。同一套因果机制对不同人的影响可以完全不同。 |
| **刨析** | 使用 Pearl 三步反事实推理：溯因（根据观测推断外生噪声）→ 行动（do 操作改变 treatment）→ 预测（在新因果机制下预测 outcome）。ITE = counterfactual_outcome − observed_outcome。符号含义：正 = treatment 增加 outcome；负 = treatment 减少 outcome。 |

### observed_outcome / counterfactual_outcome（观测结果 / 反事实结果）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 一个记录了"真实世界中发生了什么"，另一个计算了"假如原因不同，平行世界中会发生什么"。 |
| **比喻** | 就像电影《蝴蝶效应》的两个版本——你活在其中一个版本中（observed），但你可以通过反事实推理"看到"另一个版本中的自己（counterfactual）。两者的差异 = 因果效应。 |
| **刨析** | 反事实结果基于 SEM 模型计算：先用观测数据估计线性 SEM 的系数矩阵，然后用 Pearl 的 do-calculus 计算 do(T=t) 下的期望 outcome。 |

### trace_dnl（TRACE 因果边强度）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 这条因果边在 TRACE 引擎中测得的具体因果信号强度（ΔNLL 值）。 |
| **比喻** | 就像连接两个节点的"信号塔的发射功率"——功率越大，A 对 B 的影响力越强。 |
| **刨析** | 在反事实扫描表中，每条边的 trace_dnl 是该边在被过滤及截断后的最终 ΔNLL 值，并被用于计算反事实 ITE。 |

## 7. 六战士诊断卡片（Six Warriors）

六战士是一个"民主制衡"的因果验证架构。每个战士（算法）从一个独立视角审视因果图。**核心理念："不是投票，是测绘"**——每个战士测绘因果图的不同维度，不是简单的多数决。

### 🔴 TRACE（拓扑先锋·探照灯）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 六战士的核心引擎——直接从文本中扫描 token 间的因果依赖，画出因果图的"骨架"。 |
| **比喻** | 就像夜航船的探照灯——在一片黑暗（文本的无序 token 流）中，TRACE 逐字扫描，找出哪些词在"导致"另一些词出现。它绘制出的是一张"因果地形图"。 |
| **刨析** | 指标解读：`tokens` = 分析的 token 总数；`edges` = 发现的候选因果边数；`max_ΔNLL` = 最强因果信号的强度；`UNK_rate` = 未知 token 比例（破词率）。UNK>5% → 建议训练专属模型。 |
| **判定解读** | `SIGNAL_OK` = 信号充足，因果图有现实意义；`SIGNAL_WEAK` = 信号弱，因果关系需谨慎对待；`EMPTY_MATRIX` = 数据完全无因果结构。 |

### 🔵 CCM（流形力场·测谎仪）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 用非线性交叉映射测试：A 是否真的在"驱动"B（而非仅仅与 B 相关）。 |
| **比喻** | 就像测谎仪——相关性是"嫌疑人和受害者认识"，CCM 是"嫌疑人的行为轨迹可以精确地预测受害者的遭遇时间线"，后者才是因果证据。 |
| **刨析** | CCM 需要每个概念至少出现 3 次才能做交叉映射。指标解读：`eligible_concepts` = 满足 CCM 最低要求的有效概念数；`CCM_coverage` = CCM 可验证的概念占所有有效概念的比例。 |
| **判定解读** | `NARRATIVE_TEXT` = 文本是叙事文（概念稀疏无法 CCM 验证——但这本身是一个有价值的诊断信号）；`VERIFIABLE` = 可以做非线性交叉映射验证；`LOW_TRUST` = CCM 覆盖率低，非线性验证力度有限。 |

### 🟡 EDM（时序节拍器·套路探测器）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 检测概念的出现是否有"特定的时序模式"——即文本是否具有可预测的叙事套路。 |
| **比喻** | 就像分析一首诗的韵律——古诗讲究"平仄平仄平平仄"，如果你能精确预测下一个字的平仄，说明它遵循一个"套路"（即文本有很强的叙事结构）。 |
| **刨析** | 用间隔变异系数（CV）的倒数计算 ρ 值：低 CV → 高规律性 → 高 ρ。`rho_high` = ρ>0.8 的高可预测性概念个数；`rho_mid` = 0.4-0.8 的中等可预测性概念个数。 |
| **判定解读** | `HEURISTIC_STRONG_NARRATIVE_STRUCTURE` = 文本有套路化叙事结构（序列可预测）；`HEURISTIC_WEAK_STRUCTURE` = 无明显可预测性（可能是论证文或松散叙事）。 |

### ⚫ HAVOK（混沌暗杀者·X光机）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 把因果信号分解为"可线性的部分"和"混沌/非线性的部分"——检测文本中是否存在逻辑突变。 |
| **比喻** | 就像医学 X 光机——X 光照一下人体，骨骼（线性结构）和软组织（混沌部分）一目了然。HAVOK 对因果流做 SVD 分解，让线性部分和非线性部分的能量比例一目了然。 |
| **刨析** | Hankel 矩阵 → SVD → 计算 90% 能量截断秩 r。线性能量 = 前 r 个奇异值的能量占比；非线性能量 = 剩余奇异值的占比 + 最大残差分量（max_forcing）。 |
| **判定解读** | `LINEAR_DOMINANT`（线性主导 >90%）= 时间线叙事，因果流平滑；`MIXED` = 议论 + 叙事混合，有弱非线性波动；`NONLINEAR_PRESENT`（非线性 >25%）= 论证文，文本中有逻辑突变和隐藏驱动力。`linear_%` / `nonlinear_%` 是核心：线性比例越高，文本越接近"讲故事"；非线性比例越高，文本越接近"辩论"。 |

### 🟡 DoWhy+CF（反事实造物主·思想实验引擎）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 把因果图变成一个可以在思想实验中"操控变量"的模型——"假如你改变了某个原因，结果会怎样？" |
| **比喻** | 就像物理学家用数学模型做思想实验——爱因斯坦不需要真的以光速飞行就能推算出时间膨胀效应。DoWhy+CF 也不需要真的操控现实，就能用数学推导出"如果原因改变，结果会如何变化"。 |
| **刨析** | 指标解读：`ATE` = 平均处理效应（处理变量 = 原因，结果变量 = 结果）；`95%CI` = 置信区间（不跨零则显著）；`n_edges` = 因果图中有多少条边。 |
| **判定解读** | `ROBUST — 0/3 反驳` = 效应极其稳健，三项反驳全部通过；`CAUTION — X/3 反驳` = 有 X 项反驳失败，因果推断可能存在混杂。 |

### ⬜ causallearn（独立验证者·PC/GES）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 用完全不依赖 TRACE 的独立因果发现算法（PC 和 GES）从数据中重新画出因果图，与 TRACE 的图做交叉验证。 |
| **比喻** | 就像用一个完全不同的团队（不同的方法、不同的假设）重新测绘同一片地形——如果两个团队画出的地图在关键地点一致，那就非常可信。 |
| **刨析** | PC 算法（Peter-Clark 条件独立测试）：通过逐步测试条件独立性来确定因果边；GES 算法（Greedy Equivalence Search）：通过贪婪优化 BIC 分数来搜索等价因果结构。 |
| **判定解读** | `CONSENSUS` = TRACE 和 causallearn 在多个边上达成共识（最强验证）；`TRACE_ONLY` = causallearn 在该数据上功效不足（N<200 常见，这证明了 TRACE 在小样本上的独特价值）；`DIVERGENT` = 两者发现不同边（需要人工审查）。 |

## 8. 复合诊断（Compound Diagnostic）

复合诊断引擎是六战士的"合体形态"——不投票，而是从六维诊断信号中推论文本的"逻辑结构类型"。

### text_type / logic_structure（文本类型 / 逻辑结构判定）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 从六个维度（拓扑/非线性因果/时序规律/混沌/反事实/独立验证）综合判定：这段文本是"论证文"（有因果逻辑链）、"叙事文"（时间线叙述），还是"混合型"。 |
| **比喻** | 就像法医从骨骼、牙齿、DNA、衣物、指纹、毒理六个维度判断一具遗骸的身份——单一维度可能误判，但六个维度交叉验证后的结论高度可靠。同样，复合诊断用六个"算法战士"从不同角度测绘文本，得出的"文本身份"比任何单维度结论都准确。 |
| **刨析** | 复合诊断引擎评估维度：TRACE 是否有因果信号 + CCM 是否可做交叉验证 + HAVOK 是否有非线性 + EDM 是否有可预测模式 + DoWhy 是否可识别 + causallearn 是否有共识。综合得分产生最终判定。 |

## 9. 执行剖面（Execution Profile）

### execution_profile / stages（各阶段耗时）

| 维度 | 内容 |
|------|------|
| **通俗解释** | 整个分析过程被切成多个阶段，每个阶段消耗了多少毫秒——一份"时间账单"。 |
| **比喻** | 就像餐厅后厨的计时系统——你知道"切菜 12 秒、炒菜 2 分钟、摆盘 15 秒"，可以优化瓶颈。执行剖面让你知道"分词用了 0.6 秒、因果图构建用了 5 秒、反驳测试用了 0 秒（LIGHT 模式跳过）"。 |
| **刨析** | LIGHT 模式典型阶段耗时分布：tokenize(~1s) > graph(~2s) > bridge(~3s) > estimate(~0.1s) > report(~0.5s)。最重的阶段是 bridge（因果图构建+DoWhy 模型建立）。 |

## 10. 快速判断速查表

### 这个分析结果可信吗？

| 指标组合 | 判断 | 行动建议 |
|----------|------|----------|
| ATE ≠ 0 且 CI 不跨零 | ✅ 可信 | 查看反事实扫描找具体因果链 |
| ATE ≠ 0 但 CI 跨零 | ⚠️ 存疑 | 增大文本、降低 threshold、或启用 DEEP 模式 |
| 0/3 反驳通过 | ✅ 稳健 | 效应高度可信 |
| 2-3/3 反驳失败 | ❌ 不稳定 | 效应可能来自统计伪影，重新检查数据和参数 |
| CCM = "NARRATIVE_TEXT" | ℹ️ 诊断信息 | 这不是失败——它告诉你文本是叙事文而非论证文 |
| HAVOK nonlinear > 0.25 | ℹ️ 有价值 | 文本中有逻辑冲突/转折，值得人工细读 |
| causallearn = "CONSENSUS" | ✅ 最强验证 | 两种独立方法的共识——最高可信度 |
| max_delta_nll < 0.5 | ⚠️ 弱信号 | 因果结构可能不存在，或阈值设得太高 |
| condition_number > 1000 | ❌ 数据问题 | 数据矩阵病态，结果不可信 |

### LIGHT vs DEEP 模式差异

| 维度 | LIGHT | DEEP |
|------|-------|------|
| 速度 | 快（~5 秒） | 慢（~20-60 秒） |
| ATE 计算 | OLS 解析解 | DoWhy + bootstrap |
| 反驳测试 | 跳过 | 运行（随机共因 / 安慰剂 / 数据子集） |
| causallearn | 跳过 | 运行（PC + GES 交叉验证） |
| 稳定性分析 | 跳过 | 运行（bootstrap / permutation / CV） |
| 适用场景 | 快速预览、调试参数 | 正式报告、学术验证 |
