## 2. 数学基础

### 2.1 Takens 嵌入定理

给定时间序列 $x(t)$，Takens 定理保证在合适的嵌入维度 $E$ 和时滞 $\tau$ 下，延迟坐标向量：

$$\mathbf{y}(t) = [x(t), x(t-\tau), x(t-2\tau), \ldots, x(t-(E-1)\tau)]$$

构成原系统吸引子的微分同胚副本。这意味着我们可以从单一观测变量重建整个动力学系统的拓扑结构。

**实现**（`edm-takens/src/_numpy_edm.py`）:

```python
def embed_series(x, E, tau=1):
    """Takens 嵌入: x -> [x(t), x(t-tau), ..., x(t-(E-1)tau)]"""
    n = len(x)
    p = n - (E - 1) * tau
    if p <= 0:
        return np.empty((0, E))
    Y = np.empty((p, E))
    for i in range(E):
        Y[:, i] = x[i * tau : i * tau + p]
    return Y
```

### 2.2 Simplex 投影预测

Simplex 投影是 EDM 的基础预测方法。给定当前状态 $\mathbf{y}(t)$，找到其在重建流形中的 $E+1$ 个最近邻 $\{\mathbf{y}(t_1), \ldots, \mathbf{y}(t_{E+1})\}$，通过指数加权预测：

$$\hat{x}(t+1) = \sum_{i=1}^{E+1} w_i \cdot x(t_i + 1), \quad w_i = \exp\left(-\frac{d_i}{d_1}\right)$$

预测技能 $\rho = \text{corr}(\hat{x}, x)$ 随嵌入维度 $E$ 的变化揭示系统的非线性特征。

### 2.3 S-Map 非线性检测

S-Map（Sequentially weighted Local linear Map）通过局部线性回归的加权方案检测非线性：

$$\hat{x}(t+1) = c_0 + \sum_{j=1}^{E} c_j \cdot y_j(t), \quad w_i = \exp\left(-\theta \cdot \frac{d_i}{\bar{d}}\right)$$

当 $\theta = 0$ 时退化为全局线性回归；$\theta > 0$ 时赋予近邻更高权重，体现局部非线性。**非线性判定**: 若 $\rho_{\text{S-Map}}(\theta^*) > \rho_{\text{S-Map}}(0)$，则系统是非线性的。

### 2.4 收敛交叉映射（CCM）

Sugihara 等（2012）的核心洞见：若 $X$ 因果驱动 $Y$，则 $Y$ 的流形包含 $X$ 的信息，可以通过交叉映射恢复 $X$：

$$\hat{X} | M_Y = \sum_{i=1}^{E+1} w_i \cdot X(t_i), \quad w_i = \exp\left(-\frac{d(\mathbf{y}(t), \mathbf{y}(t_i))}{d_1}\right)$$

**关键判据**: 因果性的证据不是单个 $\rho$ 值，而是 $\rho$ 随库大小 $L$ **收敛**（单调增加）。本项目的收敛判据（`ccm_causality.py`）：

```python
is_converging = (total_rise > rise_threshold           # 0.05
                and spear_rho > spearman_threshold      # 0.7
                and spear_p < spearman_p_threshold      # 0.1
                and abs(final_rho) > strong_direction_rho)  # 0.2
```

**方向判据**: 比较 $X \to Y$ 与 $Y \to X$ 的 $\rho$ 大小。若 $\rho_{X \to Y} > \rho_{Y \to X} + \delta$，则 $X$ 驱动 $Y$；若两者接近（$\delta < 0.05$），则为双向因果。

### 2.5 HAVOK（Hankel Alternative View of Koopman）

Brunton 等（2017）的 HAVOK 方法通过 Hankel 矩阵的 SVD 分解识别动力学模态：

$$H = \begin{bmatrix} x(1) & x(2) & \cdots & x(p) \\ x(2) & x(3) & \cdots & x(p+1) \\ \vdots & & \ddots & \vdots \\ x(q) & x(q+1) & \cdots & x(n) \end{bmatrix} = U \Sigma V^T$$

取前 $r$ 个奇异向量 $V_r$，拟合线性算子：

$$V_r(t+1) = A V_r(t) + B v_r(t)$$

其中 $v_r$ 是第 $r$ 个（最弱的）模态，作为**强迫项**（forcing）反映系统的非线性/随机扰动。**矩阵指数**保证离散时间演化的精确性：

```python
# sovereign_havok.py
M_aug = np.zeros((n_aug, n_aug))
M_aug[:self.r_-1, :self.r_-1] = self.A_ * self.dt
M_aug[:self.r_-1, self.r_-1] = self.B_.ravel() * self.dt
expM_aug = expm(M_aug)  # scipy.linalg.expm
self.F_ = expM_aug[:self.r_-1, :self.r_-1]  # 精确离散转移矩阵
```

**Koopman 稳定性**: 离散转移矩阵 $F$ 的特征值 $|\lambda_d| \leq 1$ 为稳定，$|\lambda_d| > 1.05$ 为发散。

### 2.6 IAAFT 替代数据检验

迭代幅度调整傅里叶变换（IAAFT）生成保留原始数据功率谱和幅值分布的替代数据，用于检验非线性的统计显著性：

```python
    # 2. 傅里叶变换, 替换相位为随机相位

    # 4. 迭代直至收敛
```

**显著性检验**: 若原始数据的非线性指标（如 S-Map $\theta^*$ 处的 $\rho$）显著高于替代数据的均值，则拒绝线性零假设。

### 2.7 Gavish-Donoho 阈值

SVD 去噪的最优硬阈值（Gavish & Donoho, 2014）：

$$\lambda_{\text{opt}} = \omega(\beta) \cdot \tilde{\sigma}_{\text{med}}, \quad \beta = \frac{q}{p}$$

其中 $\tilde{\sigma}_{\text{med}}$ 是奇异值中位数，$\omega(\beta)$ 是已知函数。本项目的 HAVOK 实现中：

```python
# sovereign_havok.py
def _gavish_donoho_threshold(singular_values, beta):
    """Gavish-Donoho 最优硬阈值 (已知噪声情形)"""
    if beta >= 1:
        return np.inf
    omega_beta = lambda_coef(beta)  # Marchenko-Pastur 系数
    return omega_beta * np.median(singular_values)
```

### 2.8 Lyapunov 指数

最大 Lyapunov 指数 $\lambda_{\max}$ 量化系统对初始条件的敏感度：

$$d(t) \approx d(0) \cdot e^{\lambda_{\max} \cdot t}$$

**预测视野**: $\tau_L = 1/\lambda_{\max}$，即系统可预测的时间尺度。本项目的实现（`final_interpretation.py`）修复了 `log(0)` 偏差：

```python

```

## 3. 算法实现

### 3.1 trace-engine: 六战士因果推断

trace-engine 的 `counterfactual_hybrid` 模块实现了"六合一"因果推断管线：

1. **概念提取**: jieba 分词 + 词频统计 + 共现矩阵
2. **图构建**: 阈值过滤 + 方向检测（ΔNLL）
3. **DoWhy 估计**: 后门调整 + 倾向得分匹配
4. **反驳测试**: 安慰剂、子集、随机共同原因
5. **反事实扫描**: 对 top 边进行干预模拟
6. **CausalLearn 验证**: PC/GES/NOTEARS 独立验证

**核心数学**: ΔNLL（对数似然变化）作为因果强度的度量：

$$\Delta\text{NLL}(X \to Y) = \text{NLL}(Y | \text{context}) - \text{NLL}(Y | X, \text{context})$$

ΔNLL 越大，$X$ 对 $Y$ 的因果解释力越强。

### 3.2 trace-to-edm: 三层元因果架构

#### Layer 1: 元 SCM 参数提取

从 trace-engine 的 `result.json` 提取 20 个系统诊断不变量：
- `ate`, `ci_width`, `adj_density`, `max_delta_nll`
- `concept_count`, `edge_count`, `ccm_coverage_pct`
- `condition_number`, `unk_rate`, `consensus_score`

这些参数构成"元因果状态向量"，反映 TRACE 引擎对文本的因果推断能力。

#### Layer 2: PCA 世俗流形

使用 Qwen2.5 嵌入 + PCA 降维，将文本投影到 3 维世俗话语流形：

$$\mathbf{z}_{\text{pca}} = W_{\text{PCA}} \cdot \text{Embed}_{\text{Qwen}}(\text{text})$$

#### Layer 3: 八正道神圣坐标轴

零样本探针将文本投影到 8 个神圣坐标轴（福音、吉祥、奥美、存在、自孕、弥赛亚、Alice、觉爱）：

$$z_{\text{sacred}_i} = \cos\left(\text{Embed}(\text{text}), \text{Embed}(\text{probe}_i)\right)$$

## 9. ROUND33 更新：真实因果发现与架构债务披露

### 9.1 关键架构债务披露：game-log schema 硬编码

**P0级架构债务识别 (DEBT-ROUND33-01)**:

edm-takens-web 的 `file_management.py:_prepare_pipeline_data` (line 163-231) 强制把用户列名重映射到 game-log schema：

|---------------------|---------------|----------|
| `ate` (DoWhy ATE) | `result` | 被当作胜负判定 (row['result']==1) |
| `ate_ci_lower` (CI下界) | `kills` | 与 ate 数学恒等 (共线) |
| `ate_ci_upper` (CI上界) | `damage` | 与 ate 数学恒等 (共线) |
| `adj_density` (图密度) | `deaths` | 语义错配 |

**后果**:
1. `pipeline.py` 的 CCM 只测试 `kills→result, damage→result, deaths→result`，即 `ate_ci_lower→ate` 等 CI 边界→ate，这是**数学恒等式**（CI 定义必然），无科学价值
2. HAVOK 因输入共线退化 (`is_degenerate=true`, `r=2`)

#### 9.7.1 LIGHT 模式同质化（设计特性，非缺陷）

ROUND34-B 调查发现，TRACE LIGHT 模式对所有新闻提取相同数量的概念和因果边：

| 指标 | 所有 LIGHT 模式新闻 | 说明 |
|------|---------------------|------|
| concept_count | 12 | 所有新闻提取 12 个概念 |
| edge_count (n_significant_edges) | 12 | 所有新闻检测到 12 条显著因果边 |
| refuted_count | 0/0 | LIGHT 模式跳过 refutations（refutations_attempted=0） |

**根因**: LIGHT 模式是简化流程，使用固定概念提取窗口和简化的因果边检测。这是设计特性，非算法缺陷。DEEP/SUPER 模式才会有差异化的概念提取和因果边检测。

**对 CCM 的影响**: edge_count 和 refuted_count 在 LIGHT 模式 replay 下是常量，CCM 对常量列返回 ρ=0.0（numpy 相关系数除以0），这是预期行为。

**论文影响**:
- 本论文第5章的 EDM 分析基于 LIGHT 模式 replay 数据
- edge_count/refuted_count 的 CCM 测试结果（ρ=0.0）无科学意义，应在解读时排除
- consensus_score/max_delta_nll/concept_coverage 等非常量列的 CCM 测试结果仍然有效
